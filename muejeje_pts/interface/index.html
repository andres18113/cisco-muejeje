Muejeje runtime

The Custom Interface of the Muejeje Script Module. It is a static description: it reads nothing and calls nothing, so it reports no module state. Ask the module itself instead — runtime.identify answers with the lifecycle it recorded.

Runtime Protocol V6

The consumer-facing contract is Runtime Protocol V6. Its single entry point is mcpDispatchV6(requestJson): a JSON string in, a JSON string out, one envelope for success and failure alike.

Every admitted operation is read-only, and runtime.capabilities reports which ones they are — this page carries no copy of that list, because a copy is a list that goes out of date where nobody is looking. runtime.identify reports what the artifact can say about itself, and neither of those asks Packet Tracer anything. The platform and network operations do ask: they report what this Packet Tracer offers or holds, or the reason a reading was unavailable. Every other operation name fails closed. There is no fallback to an earlier protocol and no path that runs a caller's JavaScript.

What this module does on its own

  • nothing — it answers, and never initiates;
  • no transport, no polling and no mailbox;
  • no change to anything: every operation reads.

Privileges

The module requests all of them — every privilege Packet Tracer offers a Script Module. Muejeje is a private, local tool run by its owner, packaged as a trusted module, so it asks for the whole set rather than a minimum. That is a deployment decision, and no privilege here is claimed to be required.

Full Packet Tracer privileges is not all Muejeje capabilities. Cisco's security privileges decide which IPC calls this module's process may make. What the module offers is a fixed list of ten operations, and every one of them reads: nothing here creates, changes, powers, moves or saves anything, whatever is selected. A recorded reading of the pinned Packet Tracer binary says which privilege each known call needs — the two root calls the whole read-only surface goes through need GET_NETWORK_INFO, and two read members beneath them, a device count and a device name, need CHANGE_NETWORK_INFO — and that is evidence about those calls, not a requirement for the rest.

Whether Packet Tracer then lets a call through is its own answer. A reading it declines comes back marked unavailable, with its reason and with the interface member the reading stopped at, rather than as an answer about what Packet Tracer offers.

Module state lives in the script engine as muejejeLifecycleState(), and the same facts are reported through runtime.identify.
