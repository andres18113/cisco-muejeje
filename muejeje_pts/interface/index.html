Muejeje runtime

The Custom Interface of the Muejeje Script Module. It is a static description: it reads nothing and calls nothing, so it reports no module state. Ask the module itself instead — runtime.identify answers with the lifecycle it recorded.

Runtime Protocol V6

The consumer-facing contract is Runtime Protocol V6. Its single entry point is mcpDispatchV6(requestJson): a JSON string in, a JSON string out, one envelope for success and failure alike.

Every admitted operation is read-only, and runtime.capabilities reports which ones they are — this page carries no copy of that list, because a copy is a list that goes out of date where nobody is looking. runtime.identify reports what the artifact can say about itself, and neither of those asks Packet Tracer anything. The platform operations do ask: they report what this Packet Tracer offers, or the reason a reading was unavailable. Every other operation name fails closed. There is no fallback to an earlier protocol and no path that runs a caller's JavaScript.

What this module does on its own

  • nothing — it answers, and never initiates;
  • no transport, no polling and no mailbox;
  • no change to anything: every operation reads.

Privileges

The module requests none. Cisco's security privileges decide which IPC calls a Script Module may make, and no privilege this repository has evidence for is known to be the one a descriptor reading needs — so naming one would be a guess. A reading Packet Tracer declines therefore comes back marked unavailable, with its reason, rather than as an answer about what Packet Tracer offers.

Module state lives in the script engine as muejejeLifecycleState(), and the same facts are reported through runtime.identify.
